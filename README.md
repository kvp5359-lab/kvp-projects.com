# kvp-projects.com

Сайт-каталог моих программ: Mac-приложения, программы для Windows, расширения Chrome, дальше Android, iOS. Русский (`/`) и английский (`/en/`).

- `content.json` — список продуктов: описание на двух языках, значок, журнал изменений, платформы (у Mac — ещё
  необязательная пометка процессора, например «Apple silicon»), языки интерфейса, схема ссылок приложения и где в нём
  раздел «Лицензия».
- «Что нового» на странице Mac-приложения показывает только опубликованные версии — те, что хоть раз были в его ленте
  обновлений (по истории коммитов `../updates`). Версия, которая людям не ушла, отдельно не показывается: её пункты
  входят в следующую опубликованную.
- `/updates/` — лента обновлений всех приложений для Mac и Windows по датам с фильтрами, и RSS: `/updates.xml`, `/en/updates.xml`.
  Собираются из журналов изменений сами — `publish.sh` при выпуске обновляет их без отдельных действий.
- Версия для Windows появляется на странице продукта, в разделе «Для Windows», в ленте и RSS, только когда в реестре у неё `status: public`; `preview` на сайте не видно. Журнал у неё свой. Посмотреть заранее: `KVP_SITE_SHOW_WINDOWS=1 SITE_OUT=<папка> python3 build.py`. Что нужно в `content.json` — `.claude/rules/infrastructure.md`.
- `content.json`: `benefit` — что даёт программа (строка под именем), `gains` — три пункта «Что даёт» на странице Mac-приложения.
- `build.py` — собирает страницы в `docs/` (их и показывает GitHub Pages), а ещё `sitemap.xml` и `robots.txt`.
  Запускать после выпуска или правки списка.
- Страницы кроме каталога: `/activate/` — активация лицензии по ссылке из письма (`assets/activate.js`),
  `/privacy/` — что приложения отправляют в интернет.
- `assets/` — оформление, шрифты, значок сайта, скрипт страницы активации, `site.js` (пометка «Обновлено», фильтры ленты; без него всё тоже работает).

Подробно — `.claude/rules/infrastructure.md`.
