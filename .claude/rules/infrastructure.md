# Инфраструктура kvp-projects.com

> **Где лежит (с 25.10.2026):** `~/Проекты/kvp/core/site/` — сайт kvp-projects.com; продукты и пути — из реестра core/spec/products.json, тексты — content.json. Правила — `kvp/CLAUDE.md`, правка общего — `core/spec/rules/SHARED-CHANGES.md`.


> Общая папка kvp: правка задевает все приложения. Перед работой — `kvp/SHARED-LOG.md`; правка — по чек-листу
> `kvp/CLAUDE.md` («Общий контур и диалоги приложений»), после — запись в `kvp/SHARED-LOG.md`.

## Стек
Статический сайт без фреймворков: `build.py` (Python 3, только стандартная библиотека + `sips` macOS для значков)
собирает HTML из `content.json`, журналов изменений продуктов и лент обновлений. Оформление — `assets/style.css`
(белая «бумага», тёмные «чернила», шрифт Geist лежит на самом сайте (`assets/fonts`, без обращений к Google — адреса посетителей не уходят третьим лицам); тёмная тема по системе). Рамки, кнопка, точки списка и
подчёркивания — карандашные линии: `pencil.py` (порт карандаша Dictum, `dictum/mac/…/Overlay/Styles/Pencil`)
рисует их в `docs/assets/ink.svg`, страницы берут их через `<use>`; цвет — цвет текста. Макет — холст Claude Design
«kvp-projects.com» (https://claude.ai/artifact/V7xFSSXVpojr8stdtuZFAY).

## Архитектура
- `content.json` — каталог. Продукт: `id` (адрес страницы), `name`, `icon` (`icns` установленного приложения →
  запасной `fallback`, или `png`), `changelog` / `changelog_en`, тексты `tagline` (в `<title>`), `benefit` (что даёт — строка под именем на карточке и
  на странице), `summary`, `features` на `ru`/`en`, `gains` (`ru`/`en`: три `{title, text}` для «Что даёт» на странице
  Mac-приложения; нет — нет раздела, как у расширений),
  `ui_langs` (языки интерфейса; без `en` английская страница пишет «Interface: Russian only» — Dictum, Textum),
  `platforms`: `{kind: mac, min, arch?, feed, file, scheme, license_path}` / `{kind: chrome, store}` / позже `windows`, `linux`,
  `ios`, `android`. `scheme` — схема ссылок приложения (страница активации открывает `<scheme>://activate?key=…`),
  `license_path` — где в приложении раздел «Лицензия» (`ru`/`en`), `arch` (необязательно) — например «Apple silicon» для
  сборок только под новые Mac: пишется после требования к системе («macOS 15+ · Apple silicon»). Новая платформа у продукта = ещё одна запись в `platforms`.
- Кнопка «Скачать для Mac» появляется сама, когда в **закоммиченной** ленте `../updates/<feed>/appcast.xml` (у note-calc —
  `latest.json`; читается `git show HEAD:…`, чтобы не сослаться на файл, который `publish.sh` ещё не выложил) есть выпуск: ссылка
  `https://updates.kvp-projects.com/files/<feed>-<версия>/<file>-<версия>.dmg` (наш сервер; копия — в Releases
  `kvp5359-lab/updates`) (так называет файлы
  `core/release/mac/release.sh`). До выпуска — «Скоро». У расширений — ссылка `store` или «Скоро в Chrome Web Store».
- Главная — герой, «Свежие обновления» (последний опубликованный выпуск каждого Mac-приложения, три самых свежих:
  первый пункт версии, короткая дата, ссылка на `#v<версия>` страницы) и разделы по платформам (Mac, браузер, дальше Windows / Android / iOS — появляются сами, когда у продукта есть
  такая платформа; пока их нет — строка «Скоро — …»).
- Пометка «Бета» у каждого продукта (карточка, заголовок, строка под кнопкой) — пока в `content.json` у него нет
  `"beta": false` (поставить при выпуске 1.0). О цене на сайте не пишем (решение пользователя).
- **Пометка «Обновлено · x.y.z»** у имени Mac-приложения на карточке: дата последнего опубликованного выпуска (из журнала)
  пишется в `data-released`, пометка скрыта; `assets/site.js` показывает её, пока выпуску не больше 14 дней (сайт
  пересобирается только при выпуске, поэтому возраст считает браузер). Без JS — пометки нет.
- Страница Mac-приложения: под заголовком — плашка «Новое в x.y.z» (первый пункт версии, ссылка на `#changes`,
  пульсирующая точка выключается при `prefers-reduced-motion`), раздел «Что даёт» (`gains`) перед «Что умеет».
- «Что нового» (`id="changes"`, у каждой версии `id="v<версия>"`; ссылка на старую версию разворачивает «Предыдущие
  версии» — `assets/site.js`) — последняя версия из журнала, остальные свёрнуты. У Mac-приложения показываются только **опубликованные** версии —
  те, что хоть раз были в его ленте в **истории коммитов** `../updates` (`feed_history` в `build.py`: один
  `git log -p` на ленту — `shortVersionString` в `<feed>/appcast.xml`, у note-calc `"version"` в `latest.json`; рабочая
  папка не в счёт). Версия из журнала, которой в истории ленты нет (собрана, но людям не ушла), своим выпуском не
  показывается: её пункты входят в следующую опубликованную версию (тот же раздел — дописываются в него). Так у Dictum,
  Textum, Cliplark и Note Calc первая версия — 0.3.0, у Shotlark — 0.12.0, а пункты Note Calc 0.5.1 — в 0.5.2. Версии
  новее последней опубликованной ждут. Отдельного списка «невыпущенных» нет (поле `unpublished` убрано). Английская страница берёт `changelog_en`; если его нет (Dictum, Textum, расширения) —
  русские пункты с `lang="ru"` и строкой «The change history is in Russian» (так же в ленте обновлений и RSS).
- **`/updates/`** (+ `/en/updates/`) — лента обновлений: все опубликованные выпуски всех Mac-приложений по датам (новые
  сверху; в один день — порядок `content.json`, новая версия выше): значок, «Имя x.y.z» → `#v<версия>` страницы, дата,
  первые три пункта, «+ ещё N», «Подробнее и скачать». Кнопки-фильтры по приложениям (`aria-pressed`, `assets/site.js`;
  без JS скрыты — видно всё; `/updates/#dictum` открывает с фильтром). На странице приложения внизу «Что нового» —
  ссылка «Все обновления <имя>».
- **RSS** — `/updates.xml` (ru) и `/en/updates.xml` (en), RSS 2.0: выпуск = запись (`guid` `<id>-<версия>`, `pubDate` —
  время, когда версия впервые появилась в ленте (время того коммита в `../updates`); описание — пункты версии HTML-списком). `lastBuildDate` — самое позднее из этих времён, а не
  время сборки: без нового выпуска файл не меняется. Ссылка `rel="alternate"` в `<head>` всех страниц, в шапке —
  «Обновления», в подвале — «Обновления · RSS».
- Всё это `build.py` собирает из журналов и закоммиченных лент (`latest_mac`, `feed_history` — только опубликованное), поэтому
  `core/release/mac/publish.sh` (запускает `build.py` и коммитит `docs/`) обновляет ленту, RSS и пометки сам —
  менять его не нужно.
- `assets/site.js` — мелкие улучшения поверх страниц, которые работают и без него (пометка «Обновлено», фильтры,
  разворот старой версии). Без запросов и аналитики. Анимации карточек и кнопок — CSS, при `prefers-reduced-motion` выключены.
- **`/activate/`** (+ `/en/activate/`) — страница активации лицензии, на неё ведёт ссылка из письма покупателю
  (`license-tool issue` печатает `https://kvp-projects.com/activate/#app=<id>&key=KVP1.…`). Всё делает
  `assets/activate.js`: проверяет ключ (`^KVP1\.…\.…$`, не длиннее 2048), убирает его из адресной строки
  (`history.replaceState`, ключ остаётся в памяти и в ссылке смены языка), показывает кнопку «Открыть <приложение>»
  (`<scheme>://activate?key=…`), где вставить вручную, и «Скопировать ключ». Само приложение не открывает — без
  установленного приложения браузер показал бы ошибку. Неизвестный `app` — пояснение и список всех приложений.
  Страница и 404 — `noindex`.
- **«Как удалить»** — внизу страницы Mac-приложения (`uninstall()` в `build.py`): кнопка в приложении, что уходит и что остаётся, «Есть в версиях новее <опубликованной>» (пока лента отстаёт от `since`), свёрнутая строка для Терминала с кнопкой «Скопировать». В строке — запасное `|| echo "Перетащи <App> в Корзину вручную"`, если Finder не смог; на английской странице `command()` в `build.py` подменяет этот текст на английский (не нашёл — сборка останавливается). Данные — `uninstall` у Mac-платформы в `content.json` (`since`, `removes`, `keeps?`, `settings?`, `keep_label?`, `manual_note?`, `command`); строка — точь-в-точь из `core/kits/apple-kit/docs/UNINSTALL.md` (Note Calc — `../note-calc/.claude/rules/infrastructure.md`).
- **`/privacy/`** (+ `/en/privacy/`) — что приложения отправляют в интернет (тексты — `PRIVACY` в `build.py`), ссылка в
  подвале каждой страницы. Новое обращение приложения в сеть = поправить эту страницу.
- Поиск: у страниц `canonical`, `hreflang` (ru, en, x-default = русская), `og:*` (у страниц приложений картинка —
  значок); `build.py` пишет `sitemap.xml` (все страницы, кроме активации и 404; `/updates/` — да, RSS — нет) и `robots.txt`.
- Опознавательные поля (лента, файл, схема, минимальная macOS, «Apple silicon», пути к журналам и значкам) — из реестра
  `core/spec/products.json` (`merge_registry` в `build.py`): журналы — `~/Проекты/kvp/<продукт>/<платформа>/CHANGELOG*.md`,
  значки — `<продукт>/brand/`. В `content.json` — только тексты для людей.

## Деплой
- Публичный репозиторий GitHub `kvp5359-lab/kvp-projects.com`, GitHub Pages из папки `docs/` ветки `main`, свой домен
  `kvp-projects.com` (файл `docs/CNAME`). DNS — на Hostinger: A-записи корня на адреса GitHub Pages, `www` — CNAME на
  `kvp5359-lab.github.io`.
- Обновить сайт: `python3 build.py` → коммит → `git push` (только с «да» пользователя).
- Ленты обновлений живут отдельно (`../updates`, `updates.kvp-projects.com/…`) — приложения ходят туда, домен на них не влияет.

## Окружение и секреты
Нет. Ключ в ссылке активации стоит после `#` — на сервер он не уходит.

## Серверная логика / БД / миграции
Нет: статические файлы на GitHub Pages.

## Локальная разработка
`python3 build.py && python3 -m http.server 8787 -d docs` → http://localhost:8787 (ссылки от корня сайта, поэтому
открывать через сервер, не файлом).
- `headlines` (у продукта, необязательно): `{"<версия>": {"ru", "en"}}` — строка новости для версий, выпущенных до нового правила журнала (иначе берётся первый пункт версии).

## Продажи (с 25.10.2026)
- Блок «Бесплатно и Pro» на странице продукта, «Pro от … в месяц» на карточке и «Входит в набор…» — сами, когда у
  подписки продукта или набора в `core/spec/plans.json` `status: active` (+ `price`, `buyURL`); пока всё `draft` —
  страницы прежние. Списки «Бесплатно — всегда» / «В Pro» — `pro` у продукта в `content.json`:
  `{"free": {"ru": […], "en": […]}, "pro": {"ru": […], "en": […]}}` (тексты для людей; какие функции платные на самом
  деле — `pro` в файле правил, `kvp feature`). Посмотреть до запуска: `KVP_PLANS=<копия> SITE_OUT=<папка> python3 build.py`.
